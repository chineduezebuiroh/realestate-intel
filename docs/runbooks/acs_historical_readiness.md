# Offline ACS historical activation readiness

This advisory validator inspects local evidence. It never acquires, publishes,
accepts historical state, updates governance, resolves a production family, or
runs Source Set, canonical, serving, or Macro. No network connection or credential
is needed. Package verification does not constitute historical acceptance.

Create the explicit input template from the checked-out repository:

```sh
python -m jobs.monthly_refresh.acs_readiness \
  --repository-root "$PWD" --template /tmp/acs-readiness-inputs.json
```

Edit that JSON to supply exact local immutable inputs, then run:

```sh
python -m jobs.monthly_refresh.acs_readiness \
  --repository-root "$PWD" \
  --inputs /tmp/acs-readiness-inputs.json \
  --output /tmp/acs-readiness-report
```

Use a new output directory each time; outputs and templates must be outside the
repository. All input paths are local filesystem paths (absolute paths are
recommended); relative paths resolve from the process working directory. Original
packages are read and extracted only into a temporary directory. They are never
rebuilt or edited, even when their configuration provenance differs from current
configuration. Exit codes: 0 pass, 1 fail (contradictory/invalid evidence), 2 blocked
(missing evidence, acquisitions, or authority). Invalid top-level input produces a
fail report with unresolved scope, rather than a partial success.

## Exact input interfaces

The version is `acs_historical_readiness_v1`. The generated JSON contains:

| Field | Local interface |
| --- | --- |
| `ranges` | Each physical source mapped to inclusive `[first_year,last_year]`. Derived from existing acquisition-plan vintages through the August vintage. Narrowed or changed ranges block complete readiness. |
| `catalog` | Path to the exact acquisition catalog JSON containing `immutable_records`. Uses existing source catalog record contracts, including package/content/data hashes and provider release identity. |
| `packages` | Map from exact `artifact_id` to its original uncompressed publication `.tar` package. No extracted-directory or ZIP substitute. |
| `evidence` | Map from `census_acs1:YYYY` or `census_acs5:YYYY` to provider evidence JSON. Supports existing year-keyed preflight files, a single preflight object, or an envelope with `snapshot` and `omission_evidence`. The envelope permits separately retained monthly snapshots and exact omission receipts. |
| `selected_parents` | Optional map from product/year key to exact authoritative artifact ID when the catalog has multiple same-vintage parents. Duplicate catalog IDs always fail. |
| `accepted_august` | Exact per-source `artifact_id`, `artifact_content_hash`, `package_sha256`, seeded from August results and cross-checked with the accepted ACS family resolution. Changing these identities fails. |
| `pins` | Optional list of objects: `{"pin":"/local/pin.json","members":{"snapshot":"/local/snapshot.json"}}`. Validates pin identity/member hashes, evidence snapshot equality, and binding to the verified acquisition manifest's provider pin. |
| `governance` | Optional path to a production historical registry snapshot. Checks schema, semantic identities, configuration hashes and missing product scope/state records. Offline snapshots remain evidence requiring independent provenance review; they cannot establish current-main authority. |
| `baseline` | Optional long CSV export of previous Macro observations, described below. |
| `comparison` | Optional CSV export of existing comparison observations, with the same columns. It is never generated by this validator. |

Example package mapping (use the complete exact ID from your catalog):

```json
{"packages":{"src__census_acs1__2024-12__r1__a1f5cd392af90fcb":"/local/immutable/src__census_acs1__2024-12__r1__a1f5cd392af90fcb.tar"}}
```

Provider evidence must account exactly once for every configured geography and
variable, with exact vintage-specific returned geography identities, requested
URLs, metadata (for preflight), and omission receipts. Opaque provider identifiers
retain their existing exact-accessURL checks. Validated HTTP 204/null/sentinel
receipts establish observed unavailability only for their own cells. A population
threshold, a different vintage's eligibility, or another geography cannot supply
missing observations. ACS1 preference and ACS5 fallback are reported independently
for each annual observation key; unresolved ACS1 evidence blocks the fallback's
readiness even when an ACS5 observation exists. The 2020 ACS1 whole-vintage gap
requires separate governance and is never inferred from a missing package.

The `baseline` and `comparison` CSVs have `geo_id,series,date,value` columns.
Supported series are `income`, `population`, `price_to_income`, `payment_burden`,
`permit_intensity`, `normalized_score`, `affordability`, and `supply`. Export
annual income/population source observations at their actual December 31 dates;
do not expand them into artificial monthly observations. Derived/score exports
retain their actual dates. Duplicate series/date/geography keys, unknown series,
and nonfinite values fail. Include separate normalized-score series exports only
at the aggregate level represented by that series; this interface does not accept
multiple metrics with the same `normalized_score` key.

Comparison reports dates, counts, first/last observations, lost coverage and
DC regression rows for every eligible geography represented in the baseline.
It imposes no uniform depth requirement. Without a comparison export, verified
annual sources support income/population coverage comparison; derived history,
normalization maturity and Affordability/Supply scoring remain unresolved.
Observation counts describe supplied score maturity evidence, not recomputed
normalization eligibility. No formula, carry-forward, score or weight is run.
The annual DC fixture is illustrative, not a production Macro baseline.

## Outputs and interpretation

* `coverage.json`: complete requested and explicitly excluded product/year/geo/variable matrix.
* `summary.md`: disposition, scope counts and blocker register.
* `proposed-inventories.json`: exact independently verified parents, advisory only.
* `blockers.json`: engineering, governance and acquisition requirements with context.
* `continuity.json`: baseline comparison, when supported.
* `validation.json`: complete report, input/config fingerprints, logical availability
  potential and separate availability/acceptance/activation dispositions.

All serialized output uses stable ordering and no run timestamps. Identical local
inputs and configuration produce byte-identical reports. A blocked or failed
inventory may contain verified parents; it must not be submitted as an accepted
inventory. Readiness does not supply the approved authority/inventory IDs needed
by historical materialization. Offline governance snapshots cannot produce a
historical acceptance or activation pass, even if structurally consistent.

## Findings established from repository evidence

At the implementation base `40b950b4edda9dff30a93754735654aab0da28e1`:

* `geography_plan()` requests 163 counties, 54 CBSAs, 5 states and 1 nation
  (223 total), excluding ten Metropolitan Divisions. Existing ZIP/region flags
  remain authoritative; nothing outside this scope is substituted.
* Acquisition plans cover ACS1 2005–2024 and ACS5 2009–2024. ACS1 2020 needs
  whole-vintage gap governance. ACS5 2023 has existing complete provider evidence
  with four geography-specific HTTP 204 omissions, but no acquisition catalog entry.
* The current production historical governance registry is absent. Physical-state
  acceptance and downstream activation cannot be established.
* The exact retained August 2024 parents are ACS1
  `src__census_acs1__2024-12__r1__a1f5cd392af90fcb` and ACS5
  `src__census_acs5__2024-12__r1__2bebdc938d8c2fb6`. The catalog also contains
  other 2024 parents; selection cannot use vintage alone.

Repository evidence can verify provider accounting and configured scope, and
identify catalog gaps and accepted identities. It cannot independently verify
local acquisition package bytes or prove historical production continuity.
Operators must supply original immutable packages and retained 2024 snapshots/
omission evidence, optional source pins, governance records, and previous Macro
exports. The generated template intentionally leaves packages empty and provides
existing individual provider evidence files through 2023. Cataloged but locally
unsupplied packages are unresolved evidence, not a claim that acquisition failed.

Remaining decisions belong to the governed process: approve ACS1 2020 gap policy,
review/adopt any still-required ACS5 2023 evidence and separately authorize its
acquisition, establish production scope/governance and complete physical-state
acceptance, then separately consider logical resolution and downstream activation.
This PR authorizes none of those operations. Stop at the readiness reports.
